# Conformance

Powder Run is built to the fleet's game guidelines, and `AGENTS.md` names the
version it follows. This page is the ledger of where the repository
**knowingly falls short** of them: one row per topic, the verdict, the
evidence, and what closing the gap would cost. A rule this page does not name
is one the repository meets; a gap found and not written down here is a bug in
this page.

**Verdicts:** ◐ partial, with the gap named · ✗ not met · ⊘ a deliberate
deviation, by owner decision.

A row with no date behind it is an opinion, so every row carries the day it
was last checked against the tree. The closing step of a `maintenance` sweep
walks this table: re-check each row, re-date the ones that still hold, delete
the ones the tree has closed.

| Subject                           |  V  | Evidence, and what closing it costs                                                                                                                                                                                                                                                                                                                                                                        | Checked    |
| --------------------------------- | :-: | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| Store screenshots                 |  ✗  | The listing's rules and its generator are in (`native/store/`, `make store-metadata`), but there is no `make store-shots`: the screenshot harness is not ported, because its recipes stage frames against this game's own HUD and maps and have to be written for them — storefront work, not a rename.                                                                                                    | 2026-10-19 |
| Slots never share storage         |  ◐  | The manifest's `id`/`scope`/`start_url`/`name` and the service worker's cache id branch per slot. **The storage keys do not**: `powderrun.settings.v1`, `.records.v1`, `.campaign.v1` and the rest are keyed by origin, so `/preview/` and `/` read and write the same saves. Closing it: a slot suffix on every key, read from one place.                                                                 | 2026-10-19 |
| Unreadable saves                  |  ◐  | Every persisted structure carries its version in its key (`….v1`). An unreadable payload is not kept: `loadRecords` and its siblings fall back to an empty book or the defaults and the next save overwrites what could not be read. Closing it: a read that reports and keeps what it cannot parse, and fixtures captured from a shipped build once one exists.                                           | 2026-10-19 |
| Catalogs as data                  |  ⊘  | **By owner decision, as in the sibling games.** Maps are generated from a seed rather than authored, so the catalogs are TypeScript consts (`engine/game/defs/sled.ts`, `tuning.ts`, `modes.ts`; `mapgen/rules.ts`) rather than schema-validated data files: the type checker is the schema and a cross-reference is a compile error. Lost: a non-programmer cannot add a sled, and no mod could ship one. | 2026-10-19 |
| One command per derived asset     |  ◐  | `make icons` writes every web icon from the one authored mark. The phone app's `native/assets/icon.png` is a byte-for-byte copy of `icon-1024.png`, put there by hand: nothing regenerates it, so a change to the mark reaches the phone app only if someone remembers. Closing it: `scripts/generate-icons.mjs` writes it too.                                                                            | 2026-10-19 |
| Dependency licences               |  ◐  | `provenance.json` lists every shipped asset, and `make licences` (CI's lint job) holds every npm package in the three lockfiles to the fleet's allow-list. **The desktop app's Rust crates are not checked**: `Cargo.lock` records no licence, so covering them needs `cargo metadata` (or a `cargo-deny` step) in the desktop workflow.                                                                   | 2026-10-19 |
| Benchmarks against a baseline     |  ◐  | DEVELOPER ▸ BENCHMARK (`make bench` headlessly) times a pinned race's frames in the real build, scores it and keeps the last twenty runs. There is no committed baseline to diff against and no headless steps-per-second benchmark of the engine.                                                                                                                                                         | 2026-10-19 |
| Reference device and frame rate   |  ✗  | No reference device and no frame-rate target are written down. `make profile` measures counts, not a target, and the picture's ladders are fitted to the machine in hand rather than to a named phone.                                                                                                                                                                                                     | 2026-10-19 |
| A rule error ends the run visibly |  ◐  | The REPRO line and its URL stand a run up again, and `output-bridge.ts` keeps the engine's own log. Not established: what a thrown rule error does to a run in progress — nothing catches it.                                                                                                                                                                                                              | 2026-10-19 |
| Interface as content              |  ✗  | The HUD and menus are Preact components, not authored content with a schema and stable ids — though every word they show is a key in `pwa/src/game/strings.ts`. With no mod boundary the interface is not required to be content.                                                                                                                                                                          | 2026-10-19 |
| Text as a keyed catalog           |  ◐  | Every word the HUD and the menus show is a key in `pwa/src/game/strings.ts`, and composed lines are templates. One locale and one table, no pseudo-locale pass over the longest rendering.                                                                                                                                                                                                                 | 2026-10-19 |
| Accessibility                     |  ◐  | Keyboard, touch and pad input. **Not audited:** colour-only state on the HUD and the minimap.                                                                                                                                                                                                                                                                                                              | 2026-10-19 |
